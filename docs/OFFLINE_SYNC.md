# অফলাইন-ফার্স্ট ও অটো-সিঙ্ক সিস্টেম

Shopkeeper এখন **অফলাইনেও চলে** — পিসি ও মোবাইল দুই ডিভাইসেই। ইন্টারনেট না থাকলেও
অ্যাডমিন প্যানেল ও কাস্টমার-ফেসিং শপ ব্যবহার করা যায়; অফলাইনে করা প্রতিটা পরিবর্তন
ডিভাইসে সংরক্ষিত থাকে এবং **ইন্টারনেট ফিরলে সিস্টেম নিজেই সার্ভার ডেটাবেজের সাথে
সমন্বয় (সিঙ্ক) করে নেয়।**

---

## ১. এক নজরে স্থাপত্য: Mirror + Outbox + Replay

```
ব্রাউজার (পিসি/মোবাইল)                     সার্ভার (Cloudflare Pages + KV)
┌─────────────────────────────┐            ┌──────────────────────────┐
│  পেজগুলো  →  apiFetch()      │──অনলাইন──▶ │  /api/* routes           │
│     │            │          │            │       │                  │
│     ▼            ▼          │            │       ▼                  │
│  মিরর (IndexedDB)  Outbox   │◀──সিঙ্ক──── │  jx_store_state (KV)     │
│  (পুরো দোকানের কপি) (সারি)   │  রিপ্লে     │  + jx_ntf_*, রিপোর্ট...   │
└─────────────────────────────┘            └──────────────────────────┘
```

1. **মিরর** — প্রথমবার অনলাইনে খুললে `/api/sync` থেকে পুরো দোকানের ডেটা
   (`FullStoreData`: প্রোডাক্ট, অর্ডার, কাস্টমার, খরচ, সেটিংস…) ব্রাউজারের
   **IndexedDB**-তে সেভ হয়। নোটিফিকেশন, AI রিপোর্ট ও ডেইলি ব্রিফের ক্যাশও এখানে।
2. **apiFetch** — সব পেজ এখন `fetch`-এর বদলে `apiFetch()` (`src/lib/offline/apiFetch.ts`)
   দিয়ে কল করে:
   - **অনলাইনে:** সরাসরি সার্ভার — আচরণ আগের মতোই; সাথে মিরর ব্যাকগ্রাউন্ডে ফ্রেশ থাকে।
   - **অফলাইনে:** GET মিরর থেকে সার্ভিস হয়; লেখা (POST/PUT/PATCH/DELETE) সাথে সাথে
     মিররে প্রয়োগ হয় (ইউজার তখনই ফল দেখে) এবং অনুরোধটা **Outbox**-এ সারিবদ্ধ হয়।
     apiFetch একটা synthetic 200 Response ফেরত দেয়, তাই পেজগুলোর বিদ্যমান
     `if (res.ok)` লজিক অপরিবর্তিত থাকে।
3. **রিপ্লে (অটো-সিঙ্ক)** — ইন্টারনেট ফিরলে `sync.ts` ইঞ্জিন:
   Outbox-এর অপগুলো FIFO ক্রমে সার্ভারে পাঠায় → ব্যর্থ অপ `failed` হিসেবে সিঙ্ক
   সেন্টারে দেখায় → শেষে সার্ভার থেকে ফ্রেশ স্ন্যাপশট টেনে মিরর বদলে দেয়।
   ফলে লোকাল টেম্প আইডি (`-off-`) সার্ভারের আসল আইডিতে স্বয়ংক্রিয় বদলে যায়।

## ২. সিঙ্ক কখন চলে

- অ্যাপ লোড হওয়ার ১.৫ সেকেন্ডের মধ্যে
- `online` ইভেন্ট পেলে (ইন্টারনেট ফিরলে)
- নতুন অফলাইন পরিবর্তন কিউ হলে ৩ সেকেন্ডের মধ্যে
- প্রতি ৬০ সেকেন্ডে রুটিন চেক (৩০ সেকেন্ড থ্রটলসহ); মিরর ৫ মিনিটের পুরনো হলে রিফ্রেশ
- একাধিক ট্যাব খোলা থাকলে **Web Locks** দিয়ে নিশ্চিত হয় একসাথে দুই সিঙ্ক না চলে;
  `BroadcastChannel` দিয়ে সব ট্যাবে স্ট্যাটাস আপডেট হয়

## ৩. ডেটা আগিয়ে-পিছিয়ে থাকলে সমন্বয়ের নীতি

- **সার্ভারই চূড়ান্ত সত্য।** অফলাইন মিরর কেবল "প্রিভিউ" — রিপ্লের পরে স্ন্যাপশট
  টানা হয়, তাই সামান্য দ্বিধা সেলফ-হিল হয়ে যায়।
- **স্টক:** দুই ডিভাইস অফলাইনে একই পণ্য বিক্রি করলে রিপ্লে-র সময় সার্ভার ধারাবাহিকভাবে
  কাটে; নেগেটিভ হলে বিদ্যমান লো-স্টক/স্টক-শেষ সতর্কতা ড্যাশবোর্ডে দেখায়।
- **ব্যর্থ অপ হারায় না:** সার্ভার 4xx দিয়ে চিরকালের জন্য প্রত্যাখ্যান করলে (যেমন মুছে
  ফেলা প্রোডাক্টের এডিট) অপটা `failed` হয়ে **সিঙ্ক সেন্টারে** জমা থাকে — সেখান থেকে
  "আবার চেষ্টা করুন" বা "বাদ দিন" করা যায়। নেটওয়ার্ক/5xx এরর হলে অপ পেন্ডিং থাকে,
  পরের রাউন্ডে আবার চেষ্টা হয়।
- **ক্রম গুরুত্বপূর্ণ:** Outbox FIFO — অফলাইনে নতুন কাস্টমার আগে, তার অর্ডার পরে
  রিপ্লে হয় (অর্ডার সার্ভারে কাস্টমারকে ফোন-নম্বরে আপসার্টও করে, তাই লিংক ভাঙে না)।

## ৪. UI: সিঙ্ক সেন্টার ও ব্যানার

- **ব্যানার (সব পেজে):** অফলাইন/পেন্ডিং/ব্যর্থ অবস্থায় বাঁ-দিকে নিচে ছোট ব্যানার —
  *"অফলাইন মোড — পরিবর্তনগুলো সংরক্ষিত, ইন্টারনেট এলে স্বয়ংক্রিয়ভাবে সিঙ্ক হবে"*।
  ক্লিক করলে সিঙ্ক সেন্টার খোলে।
- **সাইডবার ব্যাজ (অ্যাডমিন):** অফলাইন/পেন্ডিং অবস্থায় নিচে স্ট্যাটাস রো; ক্লিকে ম্যানুয়াল সিঙ্ক।
- **সিঙ্ক সেন্টার:** পেন্ডিং ও ব্যর্থ অপের তালিকা (বাংলা লেবেলসহ), "এখনই সিঙ্ক করুন",
  প্রতিটা অপ "বাদ দিন", ব্যর্থগুলোর জন্য "আবার চেষ্টা করুন"।
- **অর্ডার-সাকসেস পেজ:** অফলাইনে করা অর্ডারে *"অফলাইন মোড — ইন্টারনেট এলে স্বয়ংক্রিয়ভাবে
  জমা হবে"* নোটিশ দেখায়।

| `src/lib/compute.ts` | পিওর গণিত (লাভ-ক্ষতি, ফাস্ট-মুভার, ইনভেন্টরি) — সার্ভার+ক্লায়েন্ট শেয়ার্ড |

| `src/lib/offline/snapshot.ts` | মিরর লোড/সেভ, নোটিফিকেশন/রিপোর্ট/ব্রিফ/মিডিয়া ক্যাশ, স্ন্যাপশট পুল |
| `src/lib/offline/appliers.ts` | প্রতিটা মিউটেশনের লোকাল প্রয়োগ + GET-এর মিরর-নির্ভর রেসপন্স |
| `src/lib/offline/apiFetch.ts` | fetch-ড্রপ-ইন — রিড/রাইট রাউটিং, synthetic রেসপন্স, আপলোড data-URI |
| `src/lib/offline/sync.ts` | সিঙ্ক ইঞ্জিন, শিডিউলিং, Web Locks, BroadcastChannel, রিট্রাই/ডিসকার্ড |
| `src/lib/offline/OfflineProvider.tsx` | Context + অটো-সিঙ্ক init + ব্যানার + সিঙ্ক সেন্টার UI |
| `public/sw.js` | SW v2 — শেল প্রিক্যাশ, নেভিগেশন ক্যাশ, /api/media/ cache-first |

## ৬. সীমাবদ্ধতা (স্বচ্ছতার জন্য)

- **AI জেনারেশন অফলাইনে অসম্ভব** — মডেল ক্লাউডে চলে। অফলাইনে শেষ ক্যাশ করা ডেইলি
  ব্রিফ ও রিপোর্ট দেখা যায়; চ্যাট/ইনসাইটে পরিষ্কার বাংলা নোটিশ আসে।
- **ইমেজ আপলোড:** অফলাইনে ছবিটা data-URI হয়ে সরাসরি প্রোডাক্টে সেভ হয় (সার্ভারের
  R2-ব্যর্থতার ফলব্যাক পথের মতোই)। সিঙ্কের পরে ছবি R2 URL-এ বদলাতে চাইলে সেটা
  আবার আপলোড করতে হয়।
- **প্রথম ভিজিট অফলাইনে:** ডিভাইসে কোনোদিন অনলাইনে না খুললে মিরর খালি — ওয়েব শেল
  দেখা যায় কিন্তু ডেটার লোকাল কপি নেই ("একবার ইন্টারনেটে খুললেই অফলাইনেও দেখা যাবে")।
- **লগইন অফলাইনে হয় না:** ৩০ দিনের অ্যাডমিন কুকি থাকলে সমস্যা নেই; কুকি শেষ হলে
  একবার অনলাইনে লগইন করতে হয়।
- **কুপন ভ্যালিডেশন** অফলাইনে মিররের কুপন তালিকা থেকেই হিসাব হয় — কিউ হয় না।

## ৭. পরীক্ষার নমুনা ফ্লো

1. অনলাইনে অ্যাডমিন খুলুন → মিরর তৈরি (DevTools → Application → IndexedDB → `jxshoes-offline`)।
2. সার্ভার/Wi-Fi বন্ধ করুন → পেজ রিলোড → শেল SW থেকে, ডেটা মিরর থেকে আসবে।
3. অফলাইনে একটা খরচ যোগ করুন → তালিকায় সাথে সাথে দেখাবে + ব্যানারে সংখ্যা বাড়বে।
4. POS কুইক সেল করুন → স্টক মিররে কাটবে, অর্ডার তালিকায় ঢুকবে।
5. ইন্টারনেট চালু করুন → ৩ সেকেন্ডের মধ্যে অটো-সিঙ্ক → সিঙ্ক সেন্টারে "সব পরিবর্তন
   সিঙ্ক সম্পন্ন" → অন্য ডিভাইস/সরাসরি API-তে ডেটা যাচাই করুন।
